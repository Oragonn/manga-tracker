# 📚 **Manga Tracker – Complete Project Summary (Updated October 4, 2026)**

## 🎯 **Project Overview**

A self-hosted manga/manhwa tracking application (Flask + SQLite + vanilla JS) that monitors series across **eight sources** — MangaDex, Kagane, Atsumaru, AsuraScans, HiveToons, Flame Comics, Thunderscans and Comix — with manual chapter control, automated background checking (8 series in parallel, plus one-at-a-time lanes for the two browser-driven sites), bulk operations, an activity log with undo for almost every change, hourly database backups (plus a daily CSV export and an optional daily Discord upload), multi-source support per series, saved filter/sort views, a relevance-ranked search with "Did you mean", a Kenmei-style Add Series preview, a library-wide Related Series list, a Fixes page for correcting bad chapters/tags, a Scheduler page with site up/down checks, a redesigned statistics page, series notes, a Save for Later scratch list, full mobile UI, and a single-user login gate so it can be reached from outside the home network.

This file is meant to be handed to a fresh chat/assistant to resume work without re-exploring the whole codebase. It describes **current state**, not a changelog — check `git log` for history.

## 🖥️ **Where it runs**

- **Production** is a Linux server (`oragon@oragonserver`, checkout at `~/manga-tracker`), running as the systemd service `manga-tracker`.
  - Deploy: `cd ~/manga-tracker && git pull && sudo systemctl restart manga-tracker`
  - Scripts on the server: `venv/bin/python3 scripts/<name>.py` (forward slashes, run from `~/manga-tracker` because scripts open the relative `data/tracker.db`). For long ones: `nohup ... > logs/<name>.log 2>&1 &`.
  - Production often lags `master` — several pushed commits can be waiting for a pull + restart.
- **This Windows desktop checkout is dev only.** Its `data/tracker.db` is **stale** compared with production; never trust it for "is this data right" questions. The user shares server backups (`tracker_backup_YYYYMMDD_HHMMSS.db.gz` in Downloads) for that — test against a gunzipped copy, never the real file.

## 🏗️ **Architecture**

### **Tech Stack**
- **Backend**: Python 3.9+, Flask (threaded dev server), SQLite (WAL mode), APScheduler-style background threads
- **Frontend**: Vanilla JavaScript, custom CSS (no frameworks, no build step)
- **Browser automation**: camoufox (stealth Firefox, via Playwright) for **Kagane** and **Comix** (Cloudflare)
- **Integrations**: MangaDex API, Kagane (camoufox), Atsumaru API, AsuraScans API, HiveToons (HTML), Flame Comics (`__NEXT_DATA__`), Thunderscans (WordPress HTML), Comix (camoufox + the site's own signed API), AniList (titles only, for MangaDex series — no longer used for covers)
- **Browser extension**: `extension/` (Manifest V3, v1.1.3) — helper for the Kenmei import page, Kenmei itself, source sites and the dashboard's source searches (see Extension section)

### **Starting the app**
Windows dev:
```
venv\Scripts\Activate.ps1
python -m backend.main
```
Flask binds `0.0.0.0:8080`, `debug=False, use_reloader=False, threaded=True`. **There is no auto-reload for Python** — any `.py` change is invisible until the process restarts (if a "bug" persists after a backend fix, check the process start time vs. file mtimes first). Needs a `.env` (copy `.env.example`) and `camoufox fetch` run once per venv (downloads the browser binary; without it importing the Kagane tracker crashes the whole app at startup).

## 🗄️ **Database Schema**

Tables are created/migrated by `init_db()` in `database.py` (runs at startup **and after a backup restore**). A few feature modules create their own tables lazily (`site_health`, `comix_uploads`, `comix_sync`) so they exist on any DB.

#### `series`
```sql
id, title, title_en, title_romaji, title_native,
source_url TEXT UNIQUE,            -- legacy primary link, kept in sync with the primary source
cover_url, banner_url,
status       CHECK IN ('reading','plan_to_read','on_hold','dropped','completed'),
source_status,                     -- publication status, refreshed from the PRIMARY source on every scan
source_type DEFAULT 'other',       -- CONTENT TYPE: manga/manhwa/manhua/other (not a site!)
anilist_id, alt_titles (JSON),
current_chapter REAL DEFAULT -1,   -- -1 = not started
current_volume, latest_chapter, total_chapters, latest_release, last_check, created_at,
genres (JSON),                     -- the scraped "Tags"; raw, rules applied at read time
content_rating DEFAULT 'unknown',  -- safe / mild ("Suggestive") / mature / explicit
searchable_text,                   -- normalised titles joined by '|' (see Search)
notes TEXT                         -- series note (markdown subset), max 2000
```

#### `series_sources` — one row per linked site page
`id, series_id, source_url UNIQUE, source_type ('mangadex','kagane','atsu','asura','hive','flame','thunder','comix'), is_primary, cover_url, last_check, added_at, consecutive_failures, last_error, last_failure_at, metadata (JSON: that source's own titles/genres/content_rating, used when it's removed)`.

#### `chapters`
`id, series_id, volume, raw_chapter, chapter_number REAL, title, release_date, chapter_url, is_oneshot, source_type, provider` (provider = scanlator group, Atsumaru/Comix). Wiped and re-inserted by every scan of a series.

#### Other tables
- `activity_log` — `timestamp, action_type, series_id, series_title, old_value/new_value (JSON), is_bulk, bulk_id, can_undo`. See Activity Log.
- `chapter_overrides` — per-series, per-source chapter corrections from /fixes: `is_banned=1` bans one exact `chapter_url`; `is_banned=0` replaces a chapter or injects one (`source_type='manual'`); has `provider`. Re-applied by every scan.
- `provider_bans` — Atsumaru scanlator groups banned **for one series** (`series_id, source_type, name, name_key`).
- `source_providers` — which providers each Atsu series had at last fetch (keyed by the site's own id).
- `tag_rules` — `tag, tag_key, action ('merge'|'ban'), target, target_key` (casefolded keys, one rule per tag, merges kept one hop deep).
- `custom_tags`, `series_custom_tags` — user-defined tags ("Custom Tags"), separate from scraped genres.
- `series_covers` — covers the user uploaded for a series (kept for re-picking).
- `gallery_covers` — every cover variant per series/site (`source_type, cover_url, volume, locale, note`), for the Settings cover picker. MangaDex, Atsumaru, Kagane.
- `related_series`, `related_series_from`, `related_hidden`, `related_checked` — see Related Series.
- `later_items` — Save for Later (`title, url, created_at`).
- `filter_bookmarks` — saved views (`name, is_builtin, position, filter_state JSON`); built-in "Default" seeded and protected.
- `stats_history` — per day/week/month/year `series_added`, `chapters_read`. **Day rows are never pruned** (the heatmap needs them).
- `meta` — key/value (`schema_version`, `search_text_version`, `related_tag_id`, `last_dashboard_visit`, …).
- `site_health` — per site: `status up/down, checked_at, error, checked_url, duration_ms, down_since, last_up_at`.
- `comix_uploads`, `comix_sync` — Comix's incremental upload cache (see Comix).

## ⚙️ **Core Features (current state)**

### Dashboard
1. **Series cards** — cover, title, current/latest chapter, unread badge, −/+ with hold-to-repeat (300 ms delay, 50 ms repeat; disabled at "not started" / latest), a "» Max" button that appears when hovering + on desktop (stages the latest chapter, still needs ✓), Continue/Search Ch. buttons (Search Ch. = `floor(current)+1`, so 7.01 → 8), middle-click support, a **Notes** pill (hover/tap shows the rendered note), and a yellow **missing-chapters** triangle (whole-number gaps between lowest and highest chapter; decimals fill their whole-number slot; oneshots ignored).
2. **Covers** — MangaDex cards use the `.512.jpg` thumbnail (falls back to the full image); Atsumaru/Kagane/Comix covers are cached locally under `web/static/uploads/`; covers load 1500 px ahead of scrolling.
3. **Filters** — status, sort + direction, Content Type, Tags (genres + custom tags + content rating in one dropdown, each tag include/exclude, Mature/Explicit excluded by default, search box), Publication Status, Readable On (all 8 sites; list scrolls with Select All/Clear pinned underneath), pagination with a jump-to-any-page "…".
4. **Filter Bookmarks** — saved views dropdown left of the status filter (desktop) / bottom of the filter drawer (mobile); "Save as new view" / "Update current view" / Manage Views. `applyFilterBookmarkState(fs)` is the canonical "set all filters from an object" function.
5. **Search** (see Search section) — titles, alt titles, or a pasted source link; relevance-ranked; "Did you mean" chips on zero results; "N more in Completed…" hint when other statuses/filters hide matches ("Search all statuses" / "Show anyway"); on zero results, "Search the sources for X". `/dashboard?search=<title>` runs a search across all statuses (used by Stats links).
6. **Bulk Edit** — select cards (long-press on mobile): Mark as Read, Change Status, Custom Tags (tri-state per tag, one request, undoable), Check for New Chapters, Delete. Requests run 4 at a time.
7. **Save for Later** — bookmark-plus button (desktop toolbar + mobile toolbar) opens a scratch list of titles/links (link field is a textarea: Shift+Enter new line on desktop, Return on phones). Click a title for a popover with the full text; every `http(s)` URL in it is a clickable link. Edit/delete inline. No undo (disposable list).
8. **Source Alerts bell** — series whose sources failed 3+ scans in a row, grouped into one **outage** row when ≥5 series fail on the same site (or the site check says it's down); clicking a row jumps to the series.

### Add Series (Kenmei-style preview)
- Paste one or more links (commas, spaces, new lines or glued `...https://` all split; pasting into a filled field appends). The first link is the primary.
- A valid link auto-fetches a **preview** (`GET /api/series/preview?url=`): cover, title, chapter list for "Last Read" (or type any number), status, custom tags. The fetch is cached 10 min (`_prefetched`) and reused by the actual add, so adding doesn't fetch twice. MangaDex's AniList title look-up and Kagane galleries run after the add, not in the preview.
- Source row shows "Site +N"; with 2+ links it opens a list (PRIMARY badge, each link's latest chapter / "In your library" / "Couldn't fetch", make primary, remove, paste another). Extra links already tracked elsewhere are warned about and skipped.
- **Duplicate warning**: if the title matches a tracked series, a dialog offers "Add as a source" / "Add as new series" / Cancel; the preview also shows "Shares a title with …" with "Open its settings" / "Search all N".
- Header buttons: **cross-source search** (title box → opens every site's search page in tabs; the extension can take this over with K/Y/U) and **Related** (library-wide related series list, see below).
- Mobile: compact link card that reflows full-screen into a Kenmei-like sheet once a preview loads.

### Series Settings (modal, shared desktop/mobile)
- Loads with one request: `GET /api/series/<id>/settings-data` (sources + site health, uploaded/gallery covers, custom tags, effective tags, genres list, chapters). Data is **prefetched** while the mouse rests on a card / when the mobile sheet opens; prefetches are dropped whenever any write request runs.
- Title picker (any known title), cover picker (current/uploaded/gallery/upload), chapter picker (with release dates, or manual Vol/Ch entry), status, **Custom Tags**, and one **"Type, Rating & Tags"** button (content type + content rating segmented controls + per-series tag editor working on effective tags).
- **Sources list**: green/red health dot per source (red = failing or site down, tooltip has the error), star = make primary **instantly** (logged, undoable, triggers a background rescan), add sources (comma-separated paste OK), remove (non-primary only; strips titles/tags/rating/cover/title that only that source provided, undoable), "Check Now".
- **Notes** button → Write/Preview dialog (markdown subset: headings, bold/italic/strike, code, links, lists, quotes); saves on its own, not via the Save button.
- **Related Series (N)** button (disabled with a reason when there's none) opens that series' related list on top of Settings.
- Hard layout rule: **the modal must not grow or scroll** — any new control must fit the cover's height (desktop buttons are 32 px for that reason).

### Mobile
Full responsive UI (≤768 px): hamburger nav, filter drawer, 2-column cards, bottom sheet per series (Continue, chapter nav, Go to Source, Copy URL, **Mark as Read** = latest chapter + Reading + drop the "want to read" custom tag, Edit, Delete), long-press bulk select, FABs, swipe-to-dismiss toasts. The phone layout reuses the desktop `#edit-series-modal` (the old `#mobile-settings-modal` / `openMobileEditModal` / `openMobileSettingsModal` / `addMobileNewSource` code is dead).

### Related Series
- Read **while chapters are fetched**, no separate scan: Atsumaru from the same page response; MangaDex from the status request (primary sources every scan, non-primary at most daily). "Check now" in the Related view does a full pass; Settings' Check Now forces it for one series.
- Add modal's Related view: one card per tracked series (cover, title, status pill, links to its own sources, "Show related (N)" with NEW count); relation-type chips (doujinshi/colored/monochrome hidden by default), "In library" chip, sort (newest related / newest series) and status filter, hide per tracked series (comes back when a new relation appears), red NEW badge. Related covers are fetched only when shown.
- **"Has Related"** custom tag is kept in sync automatically on every series related to *another tracked* series (deleting the tag opts out).

### Background Scheduler
- Check intervals per status: reading 30 min, plan_to_read 3 h, on_hold 1 day, dropped/completed 7 days (`get_check_interval()`; it has been left at a test value twice before — check before committing scheduler changes).
- Ticks every 60 s; 8 series scanned in parallel, each series' sources fetched in parallel; **Kagane and Comix series go through their own one-at-a-time lanes** (one browser each).
- `scan_series` merge rules (`_merge_chapters`):
  - One chapter per number. **The primary source's copy wins** whenever it has that number; other sources only fill gaps; among non-primary copies the newest date wins.
  - Dates rank undated < upload-time-only (Kagane `date_is_upload`) < real release date; an undated primary copy borrows another source's date.
  - The primary used for merging is the first **reachable** source (primary, then oldest added).
  - A source that errors keeps its stored chapters (marked stale, lose to any live copy). If every source is down and there are no overrides, chapters are left untouched.
  - A source that suddenly returns **no** chapters keeps its old ones and raises a Source Alert ("Returned no chapters (had N)"), unless every Atsu provider is banned (then other sources supply chapters).
  - `chapter_overrides` and `provider_bans` are applied on every scan.
  - `latest_release` = release date of the current latest chapter only (not max over all chapters).
  - Publication status is updated from the primary source only.
- A scan that succeeds clears a "down" site immediately (`site_health.note_site_ok`).
- Also runs: activity-log cleanup (startup + daily), backup managers, Discord uploader, the 30-min site check, the "Has Related" tag sync.

### Scheduler page (`/scheduler`)
Per-status cards (next fetch countdown, due / left to fetch (DB-derived), last scanned, live progress, Scan Now — scans every series of that status) and a **Source Sites** card: each site's up/down state, last check, error, Check / Check All Now. Probes use up to 2 of your series per site that have stored chapters.

### Fixes page (`/fixes`)
- **Chapter tab** — pick a series (search, 5 / 20 / all results), Current Chapters table (10 rows then Show more/Show all/Hide all, search by number, sort, Provider column), per-source ban of one exact link, edit a link, manually add a chapter; "Your Corrections" list. **Atsumaru Providers** section: ban/unban a scanlator group for that one series (filtered before Atsu picks one posting per chapter, so another group's copy is used).
- **Tag tab** — merge tags (a + aa → b) and ban tags. **Rules apply when tags are read, never written into `series.genres`** — deleting a rule restores everything instantly. Sort Most used / Least used / A-Z / Z-A, long lists fold with a faded peek row, Recent Changes with undo. Tag events are logged forever.

### Activity Log (`/logs`)
- 30-day retention (`ACTIVITY_LOG_RETENTION_DAYS`), **7-day undo window**; tag merge/ban events (`TAG_ACTION_TYPES`) are never cleaned up.
- Action types: `added, deleted, progress, status, edited` (title/cover/type/rating/tags/notes/primary change), `source_added, source_removed, source_cleanup, custom_tags, chapter_override_*, provider_banned/unbanned, tag_merged/unmerged/banned/unbanned, bookmark_added/updated/deleted`.
- **Two separate undo implementations** in `main.py`: single (`api_undo_log`) and bulk (`api_undo_bulk`). A new loggable action needs both. Deleting a series snapshots its sources, custom tags, notes etc. so undo restores everything.
- Inline "Undo this? Cancel / Undo" confirm (no native dialogs).

### Errors (`/errors`)
7-day rotating logs, unread count badge (desktop nav, hamburger row, dot on the hamburger icon, on every page), per-day view + Download. **Acknowledge per site** hides that site's errors from the badge until one of its failing links works again (`data/muted_error_sites.json`).

### Backups (`/backups`)
- Hourly gzip DB backups via the SQLite backup API (7-day + 2 GB cap), Series CSV tab (daily Kenmei-shaped export, 30 days), manual backup, download, **Upload Backup** (`.db.gz` or raw `tracker.db`, validated: magic bytes, size cap 1 GB, `quick_check`, required tables), **Restore** (makes a `safety_before_restore_*` copy, swaps under the DB lock, deletes old -wal/-shm, then **re-runs `init_db()`** so an older backup gets current columns).
- Optional **Discord upload**: once a day at `DISCORD_DB_BACKUP_HOUR` (Europe/Paris, default 4) the newest backup is posted to `DISCORD_DB_BACKUP_WEBHOOK_URL` (size limit `DISCORD_DB_BACKUP_MAX_MB`, default 10).

### Stats (`/stats`)
Redesigned (hand-built SVG/HTML charts, no chart library): library totals, donuts per breakdown (status, type, rating, publication status), type-by-status, sources, 30-day activity charts, 53-week heatmap, last-12-months bars, per-year list, top genres, biggest backlogs, most read, "no release in 90+ days" modal. Days with >500 chapters read (`BULK_DAY_CHAPTERS`, i.e. Kenmei imports/mass edits) are flagged bulk: hatched, and excluded from today/week/month/year, averages and streaks. Personal helper to import a Kenmei CSV row by row: per-row site searches, paste links, Skip (X), extension keys. A link that turns out to be an already-tracked series is reported as a duplicate, never merged into it.

## 🔍 **Search**

`backend/search_utils.py`:
- `series.searchable_text` = every title normalised **with word spaces**, joined by `|` (NFKC, diacritics stripped, punctuation → word break, apostrophes deleted). Rebuilt automatically at startup when `SEARCH_TEXT_VERSION` (meta `search_text_version`, currently '3') changes — bump it if the format changes.
- A query word must start at a word boundary inside one title (so "art" doesn't match "martial"); if nothing matches, a loose anywhere-match is used.
- Relevance tiers: exact title → exact alt → title starts with → alt starts with → all words in one title → spread over titles → loose. The chosen sort applies within a tier.
- Zero results → `suggestions` (one-edit "Did you mean", max 4, only series passing the other filters).
- Pasted links: `source_links.parse_source_link` → matched against `series_sources` by the site's id (slug/locale/chapter-link variations all resolve; Asura's rotating `-<8hex>` slug suffix is stripped).
- `find_same_title_series` powers the duplicate warning; `scripts/find_duplicate_series.py` lists existing pairs.

## 🔧 **Multi-Source Architecture**

- A series can have any number of sources; **linking is always user-controlled** (never automatic).
- `is_primary` source: drives Go to Source, wins the chapter merge, provides publication status and (usually) cover/title. Star in Settings = instant primary change (logged + undoable, starts a background rescan so links switch over).
- **Adding a source**: chapters merged, titles merged into `alt_titles` (incl. the source's own main title), tags unioned, rating applied by `SOURCE_RATING_PRIORITY` (`source_metadata.py`): mangadex 7 > kagane 6 > atsu 5 > comix 4 > hive 3 > flame 2 > thunder 1 > asura 0. Note: adding a higher-priority source overwrites a hand-set rating (no "manual" flag). Duplicate detection is by parsed site id (`_find_tracked_series`), 409 if the link is already tracked.
- **Removing a source** (non-primary only): drops titles/tags only that source reported, reverts the rating if it set it, deletes its gallery covers, resets cover/title to the primary's if they came from it. All recorded so undo restores them.
- Source links are stored without `?query`/`#fragment` (`clean_source_url`).
- Health: `consecutive_failures` per source (Source Alerts at ≥3, red dot at >0) + site-level `site_health`.
- Trackers raise `SiteRedirectError` ("site down or moved") when a site redirects to another host (e.g. flamecomics.xyz now 302s to its Discord — Flame is effectively dead as of 2026-10-03).

## 🌐 **Per-source notes**

- **MangaDex** (`mangadex.py`) — official API, throttled (`_delayed_get` with a lock). Keeps every tag group + demographic. Reads all `altTitles` (`collect_titles`). Status + relations come from one extra `/manga/<id>` request (primary every scan). Unnumbered uploads collapse to one 0.0 oneshot per volume, **except** when every chapter is unnumbered and each title has a distinct part number ("Part 1/2") → chapters 1..N. When a MangaDex series/source is added, AniList is searched by title to fill missing `title_en`/`title_romaji`/`title_native` and add its synonyms to `alt_titles` (`enrich_with_anilist`, best-effort; no other site gets this). **Covers always come from MangaDex** — the old AniList cover fallback was removed 2026-09-27 (`reapply_mangadex_covers.py` cleans up leftover anilist.co covers). Cover thumbnails: `<cover>.512.jpg`.
- **Kagane** (`kagane.py` + `camoufox_kagane.py`) — camoufox clears Cloudflare Turnstile (nothing is solved; the fingerprint just passes). One call: `/api/v2/series/{id}` includes `series_books`. Season-aware numbering (resets get an offset; a reset never lands on/before the previous chapter). Untitled books use the API's `chapter_no` (anchored to titled chapters, only when it never decreases); `Special Episode N` / Prologue / Extra etc. become x.01 side entries; notices (Hiatus, Break, Announcement, Afterword, Creator's Note…) are dropped; a lone unnumbered book = 0.0 oneshot. Missing `published_on` → upload time (`date_is_upload`). Gallery via `/image/<id>/compressed`. Fetches get extra time + a retry; own scan lane.
- **Atsumaru** (`atsu.py`) — plain JSON API. Several scanlator groups can post the same number: banned links/providers are skipped first, then Atsu's own upvote score picks one (release date = earliest posting). Rating from `isAdult` + `Sexual Content` tags. Covers cached locally (`_cdn_get`, separate from the API throttle). Records providers per series for the Fixes page. "Manwha" typo normalised.
- **AsuraScans** (`asura.py`) — JSON API, premium chapters dropped, no rating system (always safe → lowest priority). Rotating slug hash handled in `source_links`.
- **HiveToons** (`hivetoons.py`) — no public API; parses the series page (moved off Astro islands to a new page format on 2026-09-22). Coin-locked chapters dropped. Rating from an "Adult" genre.
- **Flame Comics** (`flamecomics.py`, source `flame`) — `__NEXT_DATA__` from `/series/<id>`; dupes keep the earliest posting; cover via `/_next/image`; rating from tags; "Coming Soon" → plan_to_read. Source-only by request: not in the extension, Kenmei import or source-search links. **Site currently gone** (redirects to Discord).
- **Thunderscans** (`thunderscans.py`, source `thunder`) — WordPress series page `/comics/<slug>/` (REST API disabled, no Cloudflare). **Free chapters only** (coin-locked early access skipped, so it can lag the site's newest). Day-only dates. Chapter numbers with labels ("25-[S1 END]") parse the leading number. Same scope limits as Flame.
- **Comix** (`comix.py` + `camoufox_comix.py`, source `comix`) — camoufox loads comix.to once and patches the site's JS so its own signed/decrypting API client can be called (~0.3 s per call). **Incremental scans**: `comix_uploads` keeps every upload seen; rescans read newest-first and stop at a known one; a full re-read happens on count mismatch, many new pages, or every 7 days. One chapter per number = earliest English upload; provider = scan group. Covers fetched through the page and cached locally. Plain `headless=True` (Kagane's humanize/geoip options get 403'd). Own scan lane; recovers when Cloudflare clearance expires mid-request; 5-min back-off after a failed browser start.

## 🔒 **Security & Remote Access**

- **Login gate** (`backend/auth.py`): one password (`AUTH_PASSWORD_HASH`, werkzeug hash), session cookie (30 days). Every route except `/login` + static requires a session (API → 401, pages → `/login?next=`; `next` must be a local path).
- **LAN bypass**: real socket address in `LAN_CIDR_RANGES` (default private ranges) skips login. **Loopback is excluded on purpose** (a tunnel connects over loopback). `Secure` cookie flag only for non-LAN requests (Flask doesn't do TLS itself).
- **CSRF**: Flask-WTF on every state-changing request — **applies to LAN too**. Token in `<meta name="csrf-token">`, attached by the fetch wrapper in `notifications.js`. `WTF_CSRF_TIME_LIMIT = None` (tokens no longer expire after 1 h while a page sits open). Changes to CSRF/auth settings need the user's explicit OK.
- **Rate limit**: 5 login attempts / 15 min per client IP (`_client_ip()`: `Cf-Connecting-Ip` only when the socket is loopback).
- Logs: failed logins (`logs/auth_*.log`), non-LAN visitors (`logs/visitors_*.log`).
- **XSS**: anything from series/tags/sources/user input put into `innerHTML` must go through `escapeHtml()`; `href`/`window.open` from external data gated by `isSafeUrl()` (http/https only). Logs page escapes titles too.
- Backup filenames are validated by regex (path traversal fix); uploads never use the client filename as a path.
- **Compression**: JSON/JS/CSS gzipped by an `after_request` hook; **HTML is not gzipped** (it carries the CSRF token → BREACH).
- Remote access: `scripts/run_tunnel.py` runs a free Cloudflare Quick Tunnel and emails/Discord-pings the changing URL (`NOTIFY_*` env vars).

**`.env` keys**: required `SECRET_KEY`, `AUTH_PASSWORD_HASH`; optional `LAN_CIDR_RANGES`, `NOTIFY_GMAIL_ADDRESS`, `NOTIFY_GMAIL_APP_PASSWORD`, `NOTIFY_GMAIL_TO`, `NOTIFY_DISCORD_WEBHOOK_URL`, `NOTIFY_DISCORD_USER_ID`, `DISCORD_DB_BACKUP_WEBHOOK_URL`, `DISCORD_DB_BACKUP_HOUR`, `DISCORD_DB_BACKUP_MAX_MB`. `.env` is gitignored; treat webhook URLs like passwords.

## ⚡ **Performance**

- `/api/series` returns each series' chapters inline (cards and the mobile sheet never refetch them); responses gzipped (a page ~1.1 MB → ~160 KB).
- **Static assets**: templates use `{{ static_url('css/style.css') }}`, which appends `?v=<content hash>`; any `?v=` URL is cached `immutable` for a year. **Never hand-write or bump a `?v=` token** — editing the file changes the URL by itself. New pages/includes must use `static_url()`.
- Caches: genre list and related-series title normalisation (input-keyed); Add preview prefetch (10 min); Settings prefetch (30 s, cleared on writes).
- Dashboard `loadPage()` calls are numbered so the newest response wins.
- Global DB lock: `get_db()`/`release_db()` hold one app-wide `threading.Lock` per connection (non-reentrant). `release_db(conn, commit=False)` rolls back; leaked locks are released in `teardown_request`, the add worker and the scan loop (`release_leaked_db`). Writes serialise; network I/O is the real bottleneck.

## 📝 **Notes for a fresh chat**
- **Never commit or push without an explicit ask for that commit** — an earlier "commit" doesn't carry over.
- **Never use `alert()`/`confirm()`/`prompt()`.** Feedback = `showNotification()`; yes/no = `showConfirmDialog()` (supports a third `alternateText` button) or an inline confirm-row swap.
- **Desktop vs mobile**: mobile UI is touched only when the request covers it; say so when a change affects phones.
- Backend `.py` changes need a server restart; templates don't; CSS/JS need nothing (content-hash URLs). After pulling a commit that adds Python *and* templates using it, restart immediately or pages can 500.
- Production is Linux — give server commands in the `venv/bin/python3 scripts/...` form.
- The local `data/tracker.db` is stale; ask for / use a server backup for data questions, and test on copies (delete a copy's `-wal`/`-shm` before reusing it).
- **UI verification harness** (the Browser pane may be unavailable and the real server needs login): run `backend.api.app` on a spare port in a thread with `backend.database.DB_PATH` pointed at a DB copy and `app.jinja_env.globals['csrf_token'] = lambda: 'x'`, then drive it with the venv's Playwright using `executable_path="C:/Users/Oragon/AppData/Local/ms-playwright/chromium-1194/chrome-win/chrome.exe"`. Importing `backend.main` turns on auth/CSRF (patch `is_lan_request` and `WTF_CSRF_ENABLED`). Patch trackers' cover dirs to a scratch folder so tests don't fill `web/static/uploads`.
- Menus that are moved to `<body>` while open (Type/Rating/Tags menu, cover menu) aren't matched by CSS scoped under `#edit-series-modal`.
- **Line endings are mixed**: `kagane.py`, `main.py`, `database.py`, `notifications.js` (and some others) are CRLF; `api.py`, `search_utils.py`, `dashboard.js`, `style.css`, `index.html` are LF. Keep each file's style.
- Any code reading `genres` for display/filtering must go through `tag_utils` with rules loaded from the **same** cursor (the DB lock isn't reentrant). Never apply tag rules at write time.
- Don't make scan-critical SQL depend on a column added by a fresh migration (a restore without migrations once crashed every scan) — restore now re-runs `init_db()`, but stay defensive.
- Chapter merging/banning must stay keyed per source (and per exact link for bans), never per chapter number globally — this bug class has been hit several times.
- The scheduler deletes and re-inserts a series' chapters on every scan, so tracker parsing fixes heal each series on its next scan (no data migration needed).
- `scheduler.get_check_interval()` values are sometimes lowered for testing — check before committing.
- If the server fails to start: `SECRET_KEY`/`AUTH_PASSWORD_HASH` missing → `.env`; `CamoufoxNotInstalled` → `camoufox fetch`; socket error → `app.run(host='0.0.0.0')`. When testing locally, check for stray processes on port 8080 (`Get-NetTCPConnection -LocalPort 8080`).
