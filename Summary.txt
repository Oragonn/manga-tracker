# 📚 **Manga Tracker – Complete Project Summary (Updated August 25, 2026)**

## 🎯 **Project Overview**

A self-hosted manga/manhwa tracking application (Flask + SQLite + vanilla JS) that monitors series across multiple sources (MangaDex, Kagane, Atsumaru) with manual chapter control, automated background checking, bulk operations, activity logging with undo, automated hourly backups, multi-source support per series, a statistics dashboard with historical trends, toast notifications, and full mobile UI across all pages.

This file is meant to be handed to a fresh chat/assistant to resume work without re-exploring the whole codebase. It describes **current state**, not a changelog — check `git log` for history.

---

## 🏗️ **Architecture**

### **Tech Stack**
- **Backend**: Python 3.9+, Flask, SQLite (WAL mode), APScheduler (background jobs)
- **Frontend**: Vanilla JavaScript, custom CSS (no frameworks/build step)
- **Special**: Selenium for Kagane (Cloudflare bypass)
- **Integrations**: MangaDex API, Kagane scraper, Atsumaru (atsu.moe) API, AniList enrichment
- **Browser extension**: `extension/` (background.js) — lightweight companion, not actively documented here

## 🗄️ **Database Schema**

Tables: `series`, `series_sources`, `chapters`, `activity_log`, `meta`, `stats_history`, `sqlite_sequence`.

#### `series` — Main series tracking
```sql
CREATE TABLE series (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    title_en TEXT,
    title_romaji TEXT,
    title_native TEXT,
    source_url TEXT NOT NULL UNIQUE,              -- Legacy: kept for backward compatibility
    cover_url TEXT,
    banner_url TEXT,
    status TEXT NOT NULL CHECK(status IN ('reading', 'plan_to_read', 'on_hold', 'dropped', 'completed')),
    source_status TEXT,                            -- Publication status
    source_type TEXT DEFAULT 'other',              -- manga/manhwa/manhua/other
    anilist_id INTEGER,
    alt_titles TEXT,                               -- JSON array
    current_chapter REAL NOT NULL DEFAULT -1,
    current_volume TEXT,
    latest_chapter REAL,
    total_chapters INTEGER DEFAULT 0,
    latest_release DATETIME,
    last_check DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    genres TEXT,                                   -- JSON array
    content_rating TEXT DEFAULT 'unknown',         -- safe/mild/mature/explicit
    searchable_text TEXT                            -- Normalized search index
);
```

#### `series_sources` — Multi-source support
```sql
CREATE TABLE series_sources (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    series_id INTEGER NOT NULL,
    source_url TEXT NOT NULL UNIQUE,
    source_type TEXT NOT NULL,                     -- 'mangadex', 'kagane', etc
    is_primary BOOLEAN DEFAULT 0,
    last_check DATETIME,
    added_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (series_id) REFERENCES series(id) ON DELETE CASCADE
);
```

#### `chapters` — Chapter history per series
```sql
CREATE TABLE chapters (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    series_id INTEGER NOT NULL,
    volume TEXT,
    raw_chapter TEXT,
    chapter_number REAL NOT NULL,
    title TEXT,
    release_date DATETIME,
    chapter_url TEXT,
    is_oneshot BOOLEAN DEFAULT 0,
    FOREIGN KEY (series_id) REFERENCES series(id) ON DELETE CASCADE
);
```

#### `activity_log` — User action history with undo
```sql
CREATE TABLE activity_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    action_type TEXT NOT NULL,                     -- 'added', 'deleted', 'progress', 'status', 'edited'
    series_id INTEGER,
    series_title TEXT,
    old_value TEXT,                                 -- JSON: before state
    new_value TEXT,                                 -- JSON: after state
    is_bulk BOOLEAN DEFAULT 0,
    bulk_id TEXT,
    can_undo BOOLEAN DEFAULT 1,
    FOREIGN KEY (series_id) REFERENCES series(id) ON DELETE SET NULL
);
```

#### `stats_history` — Historical stats snapshots (added ~Jan 2026)
```sql
CREATE TABLE stats_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    period_type TEXT NOT NULL,   -- 'day', 'week', 'month', 'year'
    period_start TEXT NOT NULL,  -- ISO format date
    period_end TEXT NOT NULL,
    series_added INTEGER DEFAULT 0,
    chapters_read INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(period_type, period_start)
);
```
Retention: day rows kept 90 days, week rows 52 weeks, month rows 24 months, year rows kept forever. Chapters-read/series-added deltas correctly handle decrements now (e.g. unreading a chapter or deleting a series subtracts, it doesn't just always add).

#### `meta` — Application metadata
```sql
CREATE TABLE meta (
    key TEXT PRIMARY KEY,
    value TEXT
);
-- Keys: 'last_dashboard_visit', 'schema_version', etc.
```

## ⚙️ **Core Features (current state)**

1. **Multi-source tracking** — multiple sources per series (MangaDex + Kagane + Atsumaru), user-controlled linking (never auto-linked), drag-and-drop primary source selection, automated chapter/metadata merging, AniList enrichment.

2. **Manual chapter control** — +/− with hold-to-repeat (300ms delay, 50ms repeat), volume-aware sorting, season-aware parsing for Kagane, confirm button disabled until an actual change is made.

3. **Background scheduler (APScheduler)** — adaptive check intervals:
   ```python
   intervals = {
       'reading': 1800,        # 30 minutes
       'plan_to_read': 10800,  # 3 hours
       'on_hold': 86400,       # 24 hours
       'dropped': 604800,      # 7 days
       'completed': 604800     # 7 days
   }
   ```

4. **Bulk operations** — select multiple series, mark as read, change status, delete, all logged to activity log with grouped undo.

5. **Activity log with undo** — 7-day undo window, 14-day retention, hover tooltips with full timestamp, bulk-safe (won't break if you manually re-add a deleted series before undoing).

6. **Database backups** — hourly, gzip compressed, 7-day retention (~35 MB typical), manual backup/restore via `/backups` UI, safety backup taken before any restore.

7. **Statistics dashboard (`/stats`)** — hero stats, reading progress, content/status/rating distribution, time-based activity (today/week/month/year, backed by `stats_history`), source/genre preferences. Chapters-read and series-added deltas are now accurate (fixed a bug where undo/unread/delete didn't properly decrement the counters).

8. **Advanced filtering** — multi-select content type, combined Tags dropdown (genres + content rating, with an **exclude** mode per tag — Mature/Explicit are excluded by default), Publication Status, Readable On (MangaDex/Kagane/Atsumaru), text search (title/alt titles/romaji/native, clearable via an inline × button), sort with direction toggle.

9. **Toast notification system** (`notifications.js`, added Jan 2026) — replaced essentially all `alert()`/`confirm()` popups across every page with top-right toast notifications (auto-dismiss 4s, manual close, contextual icons, only fires when a value actually changed). Used for series edits, bulk ops, source management, activity log undo, backup operations, and error states. Desktop and mobile both covered.

10. **Error logging** — 7-day rotating logs, "New" badge in nav, per-date viewing. Duplicate series-add attempts and DB-locking edge cases are now logged instead of silently failing (fixed Jan 2026 — duplicate detection moved to rely on the DB's UNIQUE constraint instead of a racy pre-check, and the DB lock is now released in all exception paths).

11. **Performance** — series cards render with skeleton loading placeholders while data loads, and cover images lazy-load (added Aug 2026), improving perceived load time on large libraries. Pagination handling and error display around series loading were also tightened up.

12. **Mobile UI** — full responsive design (≤768px) across every page: hamburger nav drawer, right-side filter drawer, bottom sheet for quick series actions (Go to Source / Copy URL / Delete), 2-column card grid, long-press bulk selection, FAB buttons (add/refresh/back-to-top), bulk-edit FAB menu, safe-area support, 44px touch targets. Consistent header + refresh FAB on Dashboard, Stats, Activity Log, Backups, and Errors.

13. **UI polish (desktop)** — back-to-top FAB (now on **every** page, not just the dashboard, as of Aug 2026), dropdown trigger arrows are SVG chevrons that rotate 180° when their menu is open (replaced a tiny "▾" text glyph), pagination buttons have real contrast against the page background (previously nearly invisible — `#0f172a` pill with visible border, muted-but-legible disabled arrows), disabled buttons (e.g. Refresh mid-refresh) now visibly dim instead of just blocking clicks, Tags dropdown menu is 1.6× the trigger's width so long tag names aren't clipped (still left-aligned to the button), middle-click support on Search/Source/Continue buttons, drag-and-drop source reordering.

## 🔧 **Multi-Source Architecture**

A single series can track chapters from multiple sources simultaneously (e.g. MangaDex + Kagane + Atsumaru). This is **user-controlled** — the system never auto-links sources, since same-name series aren't always the same work.

- Table: `series_sources`, one row per source, one marked `is_primary`.
- **Add a source**: series settings → "Add Another Source" → paste URL → validated by type → chapters fetched and merged.
- **Reorder / set primary**: drag-and-drop in series settings; top = primary; used for the "Go to Source" button.
- **Remove a source**: trash icon (non-primary only; must reorder before removing the primary or the last source).
- **Chapter merge logic**: dedupe by chapter number, keep whichever source's copy has the more recent `release_date`.
- **Metadata merge**: alt titles and genres are unioned across sources; cover/banner defaults to the primary source (user can override).
- All source changes are activity-logged with before/after JSON.

## 🌟 **Special Behaviors Worth Knowing**

- **Season-aware parsing (Kagane)** — detects season markers (`(S2)`, `[Season 2]`, `{S3}`, etc.) in chapter titles and applies a numeric offset so multi-season series get continuous chapter numbering instead of resetting.
- **Atsumaru (`backend/trackers/atsu.py`)** — plain JSON API, no auth, no browser automation, no Cloudflare challenge on the API routes (unlike Kagane). Series URL: `https://atsu.moe/manga/{id}`. Metadata from `GET /api/manga/page?id={id}`, full chapter list from `GET /api/manga/allChapters?mangaId={id}` (chapter numbers are already numeric, no title parsing needed). Multiple scanlator groups can post the same chapter number — deduped by keeping the most recently posted one per number. Atsumaru's own API has a typo (`"Manwha"` instead of `"Manhwa"`) that's normalized on our side. Only exposes a boolean `isAdult` flag (no granular content-rating scale like MangaDex), mapped to safe/explicit.
- **Smart search** — matches across title, English, romaji, native, and alt titles; normalized (strips punctuation/diacritics); multi-word AND matching.
- **Volume-aware sorting** — chapters sort by volume then number; chapter picker shows "Vol.3 Ch.25".
- **Hold-to-repeat** — +/− chapter buttons repeat after 300ms hold, every 50ms after that.
- **Mobile long-press** — 500ms to enter bulk-select mode; >10px movement cancels it (so scrolling doesn't accidentally trigger selection).

## ⚠️ **Kagane Cloudflare status (Aug 2026)**
kagane.to escalated its bot protection to an interactive Cloudflare Turnstile
checkbox ("verify you are human") on its API endpoints, not just the old
passive JS delay check. This blocks the Selenium client's automated fetches
(confirmed in `logs/error_2026-08-25.log`: "Stuck on Cloudflare challenge
page after 25s"). A nodriver-based rewrite was tried (per
`.chief/prds/main/prd.md`) and hit the identical wall — same Cloudflare
challenge regardless of automation library — so the migration was reverted
back to Selenium. The app does not attempt to auto-solve the checkbox (that
would be automating a CAPTCHA); until Cloudflare's risk scoring for this
traffic relaxes, expect Kagane fetches for affected series to keep failing
and logging this error rather than succeeding.

## 📝 **Notes for a fresh chat**
- The database (`data/tracker.db`) may be wiped/reset between sessions — always sanity check row counts before assuming data exists (`SELECT COUNT(*) FROM series`).
- If the server fails to start with a Windows socket error ("address not valid in its context" or similar), check `backend/api.py`'s `app.run(host=...)` — it should be `0.0.0.0`, not a hardcoded IP.
- Don't use `alert()`/`confirm()` for new UI feedback — use the existing toast system in `notifications.js` to stay consistent.
- This project has no build step — CSS/JS are edited directly and served as static files; a hard refresh (or cache-busted reload) may be needed to see changes in a browser that already cached the old stylesheet/script.
